# DESIGN.md

## 1. Структуры данных и алгоритмы

### `generateSecret(length, base, random)`

**Назначение:** генерирует секретный код заданной длины в указанной системе счисления.

**Используемые структуры данных и алгоритмы:**
- Строка `0123456789ABCDEF` содержит допустимые символы для систем счисления с основанием от 2 до 16.
- `split('')` преобразует строку в массив цифр.
- `map()` создаёт массив объектов, содержащих цифру и случайное значение.
- `sort()` перемешивает цифры по случайным значениям.
- `slice()` выбирает необходимое количество цифр.
- `join('')` объединяет цифры в итоговую строку.

Секретный код возвращается в виде строки, поэтому сохраняются ведущие нули. Функция принимает генератор случайных чисел через параметр `random`, что позволяет получать предсказуемые результаты при тестировании.

### `evaluateGuess(secret, guess)`

**Назначение:** сравнивает секретный код с догадкой игрока и подсчитывает быков и коров.

**Используемые структуры данных и алгоритмы:**
- Строки используются для хранения секретного кода и догадки.
- `toUpperCase()` приводит символы к единому регистру.
- Оператор распространения (`...`) преобразует строки в массивы символов.
- `filter()` подсчитывает быков — символы, совпадающие по значению и позиции.
- Второй вызов `filter()` определяет количество символов догадки, присутствующих в секрете.
- Количество коров вычисляется как разница между общим количеством совпадающих символов и количеством быков.

Функция предполагает, что секретный код и догадка содержат уникальные символы.

### `isValidGuess(guess, length, base)`

**Назначение:** проверяет корректность догадки игрока.

**Используемые структуры данных и алгоритмы:**
- Строка содержит допустимые символы для выбранной системы счисления.
- `toUpperCase()` обеспечивает проверку символов без учёта регистра.
- `every()` проверяет, что каждый символ входит в допустимый набор.
- `includes()` определяет, является ли символ допустимым.
- `Set` используется для проверки уникальности символов.

Функция проверяет три условия: правильную длину, допустимость всех символов и отсутствие повторений.

### `createDigitValidator(base)`

**Назначение:** создаёт функцию для проверки допустимости отдельной цифры в выбранной системе счисления.

**Используемые структуры данных и алгоритмы:**
- Строка содержит набор допустимых символов.
- Замыкание сохраняет набор допустимых цифр после создания функции.
- Возвращаемая функция проверяет, что передан ровно один символ, и определяет его допустимость с помощью `includes()`.
- `toUpperCase()` позволяет корректно проверять шестнадцатеричные символы независимо от регистра.

Такой подход позволяет создать валидатор один раз и использовать его многократно.

### `countPossibleSecrets(length, base)`

**Назначение:** вычисляет количество возможных секретных кодов заданной длины без повторяющихся цифр.

**Используемые структуры данных и алгоритмы:**
- `Map` хранит результаты ранее выполненных вычислений.
- Рекурсия используется для вычисления количества возможных комбинаций.
- Мемоизация предотвращает повторное выполнение уже вычисленных операций.

Используется формула размещений без повторений:

`P(base, length) = base × P(base - 1, length - 1)`

Условия завершения рекурсии:
- Если длина равна нулю, возвращается `1`.
- Если длина больше основания системы счисления, возвращается `0`.

Ведущие нули допускаются, поскольку каждый допустимый символ может занимать первую позицию.

## 2. Сложность алгоритмов (Big O)

Обозначения:
- `n` — длина секретного кода.
- `b` — основание системы счисления.

| Функция | Временная сложность | Пространственная сложность |
|---|---|---|
| `generateSecret` | O(b log b) | O(b) |
| `evaluateGuess` | O(n²) | O(n) |
| `isValidGuess` | O(n × b) | O(n + b) |
| `createDigitValidator` | O(b) при создании и O(b) при проверке | O(b) |
| `countPossibleSecrets` | O(n) без кэширования, O(1) при попадании в кэш | O(n) для стека рекурсии |

### Обоснование

- **`generateSecret`:** создание массива занимает O(b), сортировка — O(b log b). Сортировка определяет общую временную сложность. Для хранения массива требуется O(b) памяти.
- **`evaluateGuess`:** проверка каждого символа догадки через `includes()` может потребовать просмотра всей строки секрета. Поэтому временная сложность составляет O(n²). Для массивов символов требуется O(n) дополнительной памяти.
- **`isValidGuess`:** проверка допустимости каждого символа через `includes()` занимает до O(b). Для всех символов получается O(n × b). Дополнительно `Set` хранит до n символов.
- **`createDigitValidator`:** создание набора допустимых цифр занимает O(b). Одна проверка также может потребовать O(b), поскольку используется `includes()`. Замыкание хранит строку допустимых символов.
- **`countPossibleSecrets`:** при первом вычислении рекурсия выполняет не более n вызовов, поэтому временная сложность составляет O(n). Результаты сохраняются в `Map`, что позволяет получать ранее вычисленные значения за O(1) в среднем. Глубина стека рекурсии составляет O(n).

## 3. Принципы чистого кода

В проекте применяются следующие принципы:

- **Разделение ответственности (Single Responsibility Principle):** каждая функция выполняет одну конкретную задачу — генерацию кода, проверку догадки, сравнение символов или подсчёт возможных комбинаций.
- **Чистые функции:** функции игровой логики не зависят от DOM и не изменяют внешнее состояние. Их результаты определяются входными параметрами.
- **Понятные имена:** названия функций и переменных отражают их назначение (`generateSecret`, `evaluateGuess`, `isValidGuess`, `bulls`, `cows`).
- **Неизменяемость данных:** для обработки данных используются методы массивов, которые создают новые массивы, вместо изменения исходных строк и массивов.
- **Внедрение зависимостей:** `generateSecret` принимает генератор случайных чисел через параметр `random`, что упрощает тестирование.
- **Повторное использование кода:** `createDigitValidator` позволяет создавать и повторно использовать валидатор для выбранной системы счисления.
- **Мемоизация:** `countPossibleSecrets` сохраняет результаты вычислений, избегая повторной работы.
- **Тестируемость:** игровая логика отделена от пользовательского интерфейса, поэтому каждую функцию можно тестировать независимо.
